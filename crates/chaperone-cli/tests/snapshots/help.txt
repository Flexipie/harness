Run many coding agents in lanes, with the process enforced in code

Usage: chaperone [OPTIONS] <COMMAND>

Commands:
  work       Leased work records. Claim an item before working on it, heartbeat while you hold it, hand it off when you stop
  spec       The dispatch spec of a parent issue, versioned. /dispatch writes it, /issue and /ship read it
  check      Check results a fresh session records for a lane: plan check, quality gate, merge verdict, smoke and kept tests
  reviews    Daisy's review jobs, as recorded in the ledger. The worker stays in daisy; lanes keep `daisy-cli reviews local` and `reviews get --wait`
  jobs       Recorded daisy jobs
  usage      Token usage per provider message, read from a lane's transcripts
  attention  Interventions on a lane by the orchestrator or the owner
  dossier    The agent-only record of an issue key: notes, and one capped read of what the ledger knows about the key. Data for agents, never a gate
  overlap    Per file, the open lanes touching it: each lane's newest handoff (changed_files), then the commits on its worktree's HEAD since the merge-base with origin, all git calls within 5 s. Shared files first. Call it before starting work
  stats      R11's lane and cohort numbers, read from the ledger: claim to merge, tokens, peak context, attention, checks and the verdict on the merged head. A number nothing records yet is null, and `missing` names what it needs
  impact     The files that depend on these Rust files, nearest first: module nodes and import edges read with tree-sitter from the worktree, facts cached by content per origin. Each depth says if it is exact or a lower bound; at most 500 files listed
  migrate    Create the ledger, or migrate it to this binary's version after a backup. Refuses a file that is not a Chaperone ledger
  help       Print this message or the help of the given subcommand(s)

Options:
      --db <DB>          Path to the ledger (defaults to chaperone/ledger.db in the user data dir)
      --format <FORMAT>  Output format: json is one {ok, data, meta} object; jsonl is one item per line followed by a trailer that is the only line with an `ok` key [default: json] [possible values: json, jsonl]
  -h, --help             Print help
  -V, --version          Print version

Every command prints one {ok, data, meta} object on stdout, or an {ok: false, error, meta} object on stderr. Exit codes: 0 ok, 1 error, 2 usage, 3 schema mismatch, 4 conflict, 5 runtime unavailable. Only `chaperone migrate` creates or migrates the ledger; every other command exits 3 on any other schema version.
